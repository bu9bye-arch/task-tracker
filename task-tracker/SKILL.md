# 任务记录

## 何时使用

使用本 skill 的典型情况：

- 用户明确要求保存任务状态、建立台账或准备交接。
- 任务会跨会话、并行推进，或需要用户在阶段之间确认。
- 任务包含多次尝试、验证、回退、阻塞或方案切换。
- 涉及外部写入、生产、发布、数据、权限或其他需要审计的高影响动作。

一次性答疑、单文件小改、无需后续接手的短任务通常不建卡。已有项目卡时更新它，不创建平行记录。

## 目录与所有权

先读取项目入口、AGENTS、任务注册表和现有活跃记录，遵循项目已经确定的目录、编号和状态命名。项目没有约定时，先提出一个目标目录和稳定编号，再创建文件；不要为了套用模板搬迁旧记录。

注册表是可选的。只有任务较多、需要交接、用户确认或存在发布门禁时才维护热索引；长证据、日志和完整 diff 留在任务卡或产物中。

## 最小任务卡

任务卡至少说明：目标、验收标准、当前状态、下一步责任方、相关路径、关键发现、决策、尝试结果、阻塞、验证、交付物和待确认事项。使用 [task-card-template.md](references/task-card-template.md) 时只复制适用字段。

状态应能表达 `new`、`in_progress`、`blocked`、`waiting_user_confirm`、`done` 或项目既有等价状态。状态变化、用户授权、关键证据和范围变化要记录时间与依据。

## 更新节奏

- 创建或接手时写短状态快照和下一步。
- 每次实际修改、重要验证、决策、阻塞或授权后更新；无新事实时不要重复刷新。
- 长输出先摘要，必要原文放到项目允许的产物或日志位置，并在卡中保留链接和结论。
- 记录结论等级：已确认、证据充分但未闭环、待验证。
- 不写入密钥、Token、完整环境变量、未脱敏个人数据或不必要的生产细节。

## 高影响与收尾

高影响任务记录用户授权范围、影响面、验证门槛和回退方式；具体发布、预览和生产字段由项目 runbook 负责，本 skill 不复制一套平台流程。

完成前重读目标和验收标准，逐项标记已验证、部分验证、未验证和待确认。只有用户确认和必要验证都满足时才标记完成；未完成的任务保留在项目规定的活跃索引中。
